03DataDone

Read-only SQLite and MySQL connection

Mon 9 Nov 2026, 08:00–17:00

Goal

One data layer that the demo can use today and the real server can use later, and that can never write.

Work

Db.php speaks SQLite and MySQL through prepared statements. The SQLite file is opened read-only. On MySQL the session is set to TRANSACTION READ ONLY. The few functions that differ between the two engines, such as month and full name, live in this class so each query is written once.

Result

A table in the demo file can be counted. A write on the same connection is rejected. Switching the driver in config.php does not require a second copy of the queries.

04FoundationDone

Login, session and CSRF

Mon 9 Nov 2026, 08:00–17:00

Goal

Two kinds of login, with a session that another site cannot reuse and a token on every request that changes data.

Work

login.php, logout.php and bootstrap.php start a session named gos_session. The cookie is HttpOnly and SameSite=Lax, and it is marked Secure only when the site itself is on HTTPS. Every changing request must send the CSRF token. admin sees the whole company. roberto is limited to capo_area_id 1. Passwords are stored as hashes, not as text.

Result

Both demo accounts can log in and log out. An API call without the CSRF token is rejected. A zone manager's later queries are tied to the id stored in this session.

07DataDone

Thirteen verified queries and zone scope

Tue 10 Nov 2026, 08:00 – Wed 11 Nov 2026, 17:00

Goal

Keep every number inside tested queries, and stop a zone manager from seeing another zone even if the model asks for it.

11AgentDone

Agent loop and JSON tool mode

Thu 12 Nov 2026, 08:00–17:00

Goal

Turn one question into a tool call, a verified query, and a short answer, and stop if the model keeps going.

Work

Agent.php sends the question with a system prompt: answer in the language of the question, every number must come from a tool, start with who, what and the period, format amounts the Italian way, and refuse any request to change data. Native tool calling is the default. tool_mode set to json is the path for a model that cannot call tools. If the provider rejects a malformed tool call, the loop tells the model and tries once more. Steps are capped.

Result

A sales question calls at least one tool. The answer does not contain a number that is not in the tool result. A question outside the data is refused and two example questions are offered.

Tool API for an external agent

Mon 16 Nov 2026, 08:00–17:00

Goal

Let another agent, for example a Python service, run the same verified queries without going through the chat model.

Work

api/tool.php lists the tools on GET and runs one on POST. The body is the tool name, the arguments, and an optional capo_area_id.
